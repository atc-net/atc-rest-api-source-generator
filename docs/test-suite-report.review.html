Negative control

The test MatrixVerdicts_FailRegressedResults feeds every verdict rule a correct result, which must pass, and one regressed result per failure mode, which must fail. The regressions it covers:

  • a changed or lost value, or a JSON string where a message belongs;
  • a wrong custom-model field;
  • the default body on the status's own accessor;
  • an undeclared status without its raw Content;
  • a wrong TypeScript arm, a missing named arm in the generated union, or a wrong detail;
  • a wrong default body on the wire, or a 5xx detail outside Development;
  • a missing Retry-After on a 429;
  • a handler value missing from its ProblemDetails;
  • a lost XML body in C#;
  • a stub wire mismatch;
  • a parsed model on a TypedClient Result error.

Bugs the matrix found, now fixed (each reproduced by a failing test first)

  • C#, a declared error model over a foreign body. The accessor threw InvalidContentAccessException; it now reads the body leniently.
  • TypeScript Axios, a JSON-string error body. It was parsed twice: "42" became a number.
  • C#, a declared string or text status with no body from the handler. The accessor gave the host wiring's ProblemDetails as JSON text; it now gives its message.
  • C#, application/xml / application/octet-stream error bodies. Content and the typed accessors were empty, because Atc.Rest.Client keeps such bodies as bytes. The generated client now reads them as text.
  • C# TypedClient, Result style. A download's error body was not in Content.
  • TypeScript Axios. Kept application/octet-stream and untyped error bodies as the body.
  • TypeScript Fetch. Dropped XML error bodies, although it reads XML success bodies as text.

Atc REST 3.0 readiness

State of feature/error-body-3.0 (generator), 14 October 2026.

  • Atc.Rest.MinimalApi 3.0.0 is released on nuget.org. The tests and the samples have referenced the package since 12 October; the temporary project references are gone.
  • Atc.Rest.Client is released up to 2.6.0, with every library issue this branch raised. 2.6.0 is the minimum for the EndpointPerOperation client and the TypedClient's Result style (ATC_API_DEP011).
  • The generator 3.0 is not released. The branch and the wiki are committed locally and not pushed yet.

The numbers on this page come from the run that wrote it: the verdicts per matrix on the Overview tab, the compile gate and the diagnostics on Feature support, and the Showcase apps under Playwright. The commit the run was made from is in the page header. These notes are written by hand, so they carry no counts - a test checks that, so editing this page alone can turn a run red. Since the 5 October notes

  • Server.
    • A factory for an error status that declares a model takes the model; a result factory takes the headers its response declares.
    • Every server gets the one-call host wiring (Add{Api}Api() / Map{Api}Api()), also without Atc.Rest.MinimalApi.
    • Validation messages name the value as it was sent; a server without the ValidationFilter still rejects a missing required parameter or property.
    • The parameters build and bind through the Request Delegate Generator, and the JSON writes are trim- and Native AOT-ready (ATC_API_AOT001 for what still binds by reflection).
  • Parameters and bodies. Objects in the query (deepObject, form with explode), arrays in the path and headers, a JSON part of a multipart form, a oneOf part, charset-aware text bodies, HEAD and OPTIONS operations, and new diagnostics for what cannot be bound or sent (ATC_API_OPR037, OPR038, OPR040).
  • Streaming.
    • Server-Sent Events, JSON Lines, JSON arrays, JSON Text Sequences and multipart/mixed are read the same way in every client, including what other servers put between records.
    • A streamed EndpointPerOperation operation has its own result class with typed errors and declared headers.
    • x-sse-item-events names the events that carry items.
    • An event stream can be resumed: the server sets each event's id, every client gives the last id back.
  • SignalR hubs (x-signalr-hubs). The server gets the hub contract and the C# clients a typed hub client; hubs declare methods beside events; the TypeScript client reads hubs with the same parser and its React hook connects to the hub on the server, reconnects after a close and is StrictMode-safe.
  • TypeScript. Every SignalR hub compiles, Zod schemas carry a default written next to a $ref, and the clients read bodies by their charset.
  • Tooling. Overlays from the CLI options file; the CLI cannot hang on a tool it runs; one rule names the root namespace for the server, the handlers and the client.
  • Report. Every matrix also runs from its specification as an OpenAPI 3.1 document; the feature matrix covers the stream formats on the wire, a resumed event stream and SignalR hubs; the Changes tab keeps the run history.
  • Showcase. Live streams in every format with a drop and a resume, a live price feed with a heartbeat, a replay buffer and fan-out, and the notifications hub generated from the specification in all three apps.

Fixed in the 5 October round

  • Every status below 400. 2xx and 300 write their declared body, 205 and 304 none, the redirects write Location, a 1xx gets no factory (ATC_API_OPR030); the C# client never reads a 3xx as an error; TypeScript has the arms notModified and redirection.
  • TypeScript naming. A naming strategy that differs from the API's casing renames the wire too (helpers/wireNames.ts).
  • Error bodies. String accessors give a problem's message; XML and binary error bodies reach Content; a declared error model reads a body of another shape leniently; Fetch and Axios read success and error bodies by one rule.
  • Models and enums. Properties are written under their exact spec names; a server string enum is a string in every host; the clients' enums are extensible (extensibleEnums: false keeps the classic enum).
  • OpenAPI Overlays in the build and the CLI.
  • A broken specification is reported, never a crash (a fuzz test over every scenario).

Known limitations (documented)

  • HttpClient.Timeout (100 s) caps long per-operation retry timeouts; a long-lived stream needs a client of its own (Working with C# Client).
  • The build finds multi-part specs by the {Base}_{Part}.yaml convention only.
  • Node's fetch rejects every 407 response, so the Fetch client cannot be observed on 407 in Node. Browsers behave differently; this is a platform limit, not a client one.
  • The framework's event-stream writer has no comment line, so a server heartbeat is a named event that the clients read past.
  • A SignalR event whose name is no C# identifier cannot be a method of the typed hub client interface; the server sends it with the generated contract's Send…Async.
  • Not exercised by the matrix: the How it was tested tab lists everything the E2E run does not cover.
